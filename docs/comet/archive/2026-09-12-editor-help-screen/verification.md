## Risks and skipped work

- A6/A30/A57 glyph prediction is wrong about egui, not about the code: egui 0.27.2 format_shortcut only uses the command/shift symbols if TextStyle::Body can render ALL of the four modifier glyphs. The bundled Proportional family contains U+2318 but not U+21E7/U+2325/U+2303, and the app never calls set_fonts, so on macOS the help window will actually read 'Cmd+Z' and 'Shift+Cmd+Z'. Amend the spec text or add a font covering the four symbols - do not hard-code the strings.
- Non-mac modifier order also differs from the spec's literal text: egui emits ctrl-then-shift ('Ctrl+Shift+Z') where A6/A30 write 'Shift+Ctrl+Z'.
- Tools entries print each kind's gloss rather than the literal kind word, so a reader cannot recover the JSON type string verbatim.
- is_tool_implemented duplicates rather than shares main.rs's tool-name match, so the two can silently drift if a new real mode is added to update. No test cross-checks them.
- Sections render no Key/Effect header row; the two-column structure comes only from the Grid.
- On the single frame Escape or F1 closes the window, a click inside the old rect would still be swallowed. Escape/F1 are not clicks, so unreachable in practice.
- Symmetric with the intended toolbox-drag fix: an entity or vertex drag already under way also continues while the cursor passes over the help window, and its release inside the window still calls save_state().

## Conclusion

All 62 items re-derived from src/help.rs, src/main.rs and the egui 0.27.2 sources without relying on the builder's account; every one holds. The iteration-3 change is sound in both directions: the !pointer_over_help guard now sits only on the drag-START branch (main.rs:932), so a press inside the help window still cannot begin a toolbox drag and - via the separate help_click / secondary_over_help guards - still cannot place, select, delete, finalise a polygon or dirty has_unsaved_changes, while the move block stays unguarded so drag_start is rewritten every frame and an in-flight drag crosses the window without freezing or jumping. Non-modality survives the guards: arrow scrolling, menus and outside clicks are untouched, and wants_keyboard_input() stays false because nothing in the help body requests focus. The one substantive gap is documentary: the code uses ctx.format_shortcut exactly as mandated, but egui's glyph check falls back to 'Cmd+Z' / 'Shift+Cmd+Z' on macOS instead of the symbols the spec predicts, so the spec's illustrative strings should be corrected.
