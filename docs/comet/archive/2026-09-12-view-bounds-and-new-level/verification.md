- scroll.rs:206-243 (the_far_bound_leaves_exactly_one_viewport_of_slack) is close to tautological: the asserted expression m.offset.x - strict.x - viewport.x expands to m.offset.x - level.x, and the visible_far assertions cancel the viewport term too, so iterating four viewport sizes adds nothing. - The Unsaved Changes window is non-modal (main.rs:1266): while it is open the canvas, toolbox and menus stay live, so the user can keep editing (or re-trigger New Level, or start play mode and then Discard) underneath the pending prompt. Not covered by any acceptance item.

Harmless here (the next editor step re-clamps) and pre-existing, but it is the one way the in-bound-by-construction argument for A6/A47 leans on the re-clamp rather than on the capture.
- The archived specs still carry the superseded wording (docs/comet/specs/canvas-scrolling/spec.md:12, docs/comet/specs/level-size/spec.md:35), and the editor-help-screen spec's Menus table still lists Background Image first. ## Conclusion

I judged all 56 acceptance items independently against the implementation and found every one satisfied. The scroll bound is implemented where the brief's D5 said it should be - inside ScrollModel::step_axis (scroll.rs:86-95) - so the far bound pins the offset and zeroes velocity in exactly the same branch structure as the origin clamp, and the maximum is a per-step parameter fed from resolved_level_size() each frame (main.rs:1361), which is what makes the bound track the level size live in both directions. Play mode is exempt because the step is skipped wholesale under if self.play.is_none(), and level_size::resolve guarantees at least 1 px per axis so the range cannot invert. New Level is now the first item in the File menu, above Load Level, with the identical play.is_none() gate and the identical "Stop play mode first" disabled hover text - I re-checked this afresh and the previous cycle's ordering defect is gone. The reset itself (main.rs:283-309) is a pure in-memory assignment from BlankLevel, clears every field the spec lists including the open Level Size dialog and last_click_pos, marks the editor clean from the blank content's own hash, and touches no file; the Save path in the shared confirmation advances only on Ok(true) from a real fs::write. Test coverage is genuine rather than tautological where it matters - a_working_editor() dirties every field before asserting it is cleared, and dirtying_a_new_level_is_noticed rules out a blanket-clean marker. The main soft spot is the one-viewport-slack test, whose assertion cancels the viewport term algebraically and so proves only offset == level_size; combined with the window-relative world origin, the level-edge-at-the-viewport's-near-edge claim is approximate in y by the menu-bar height. Menu position, hover text and the dialog wiring remain inspection-only, which is precisely where the last cycle failed, so they are worth a manual glance before archiving.
